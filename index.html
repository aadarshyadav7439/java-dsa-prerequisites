Java Basics

The absolute floor: how Java stores and reads data. Nothing fancy — just make sure these are reflexive before you move on.

› Variables & Data Types

Concept

Java is statically typed — every variable has a fixed type declared up front, and that type never changes. The primitive types you'll actually use in DSA are int, long, double, char, and boolean.

Example

Main.java
int age = 20;
long population = 1_000_000_000L;
double price = 99.99;
char grade = 'A';
boolean passed = true;
Remember
  • int is 32-bit and holds up to ~2.1 billion — fine for most things, but overflows silently.
  • long is 64-bit; append L to the literal or it's treated as int first.
  • double is the default choice for decimals in DSA problems.
  • Underscores in number literals (1_000_000) are just for readability — the compiler ignores them.
Common Mistake

Forgetting to use long for values that can exceed ~2.1 billion (factorials, products of two large ints) — the answer silently wraps around into a negative number instead of throwing an error.

DSA Connection

Problems that ask "how many ways to..." or multiply two large counts almost always need long. If a result looks impossibly negative, overflow is the first thing to suspect.

› Type Casting

Concept

Casting converts a value from one type to another. Widening (int → long → double) happens automatically. Narrowing (double → int) needs an explicit cast and can lose data.

Example

Main.java
int a = 10, b = 3;
double result = (double) a / b;   // 3.333...
long big = 5000000000L;
int truncated = (int) big;        // data loss, be careful
Remember
  • Integer division truncates: 10 / 3 is 3, not 3.33 — cast before the division, not after.
  • Casting a char to int gives its Unicode value: (int) 'A' is 65.
  • Narrowing casts can silently lose precision or overflow — Java won't warn you at runtime.
Common Mistake

Casting after the division: (double)(a / b) still does integer division first, then converts the already-wrong result.

DSA Connection

Comes up constantly when computing averages, midpoints ((low + high) / 2), or percentages inside loops.

› Operators

Concept

Arithmetic (+ - * / %), relational (== != < > <= >=), logical (&& || !), and assignment operators. The modulus operator % is used constantly in DSA for parity checks and circular indices.

Example

Main.java
int n = 17;
boolean isEven = (n % 2 == 0);
int lastDigit = n % 10;               // 7
int wrapped = (i + 1) % arr.length;   // circular index
Remember
  • % on negative numbers can return a negative result (-7 % 3 is -1) — different from some other languages.
  • && and || short-circuit: the second operand isn't evaluated if the first already decides the result.
  • ++i vs i++ only differ when the expression's value is used immediately.
Common Mistake

Using = instead of == inside a condition — if (isEven = true) compiles and silently reassigns instead of comparing.

DSA Connection

Modulus powers circular arrays and hashing; short-circuit && is what makes a check like node != null && node.value > 0 safe.

› Input with Scanner

Concept

Scanner reads input from System.in. It's the easiest way to read numbers and words, and the standard choice for small inputs and local testing.

Example

Main.java
Scanner sc = new Scanner(System.in);
int n = sc.nextInt();
String line = sc.nextLine();
sc.close();
Remember
  • import java.util.Scanner; is required.
  • nextInt() leaves the trailing newline in the buffer — a nextLine() right after returns an empty string unless you consume it first.
  • Fine for small inputs, but noticeably slower than BufferedReader on large ones.
Common Mistake

Mixing nextInt() and nextLine() without an extra sc.nextLine() in between, which "skips" the next line read.

DSA Connection

Fine for interview-style problems and local testing of your own array/string solutions.

› Faster Input with BufferedReader

Concept

BufferedReader reads raw text faster than Scanner because it doesn't parse types for you — you read a line as a String and convert it yourself.

Example

Main.java
BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
int n = Integer.parseInt(br.readLine().trim());
String[] parts = br.readLine().split(" ");
int first = Integer.parseInt(parts[0]);
Remember
  • Everything comes back as a String — convert with Integer.parseInt(), Long.parseLong(), etc.
  • readLine() throws IOException, so wrap it or declare throws IOException.
  • Use split(" ") (or split("\\s+")) to break a line of numbers apart.
Common Mistake

Forgetting .trim() before parsing — a trailing space or \r makes parseInt() throw.

DSA Connection

Reach for this when Scanner is genuinely too slow (competitive programming with large n). For everyday DSA prep, Scanner is usually enough.

Conditions & Loops

Every DSA solution is loops and branches wearing a fancier name. Get comfortable tracing them by hand.

› if / else-if / else

Concept

Branches execution based on a boolean condition. else-if chains check multiple conditions in order; only the first true branch runs.

Example

Main.java
if (n < 0) {
    System.out.println("negative");
} else if (n == 0) {
    System.out.println("zero");
} else {
    System.out.println("positive");
}
Remember
  • Conditions must evaluate to boolean — Java won't accept 0/1 as true/false.
  • else-if is really just else { if (...) }.
  • Braces are optional for single statements — keep them anyway.
Common Mistake

Dropping the braces and adding a second statement under an if, assuming both lines are conditional when only the first one is.

DSA Connection

This is the entire logic of binary search, base cases in recursion, and validating input before processing it.

› switch Statement

Concept

An alternative to a long else-if chain when comparing one variable against several fixed values.

Example

Main.java
switch (grade) {
    case 'A':
        System.out.println("Excellent");
        break;
    case 'B':
        System.out.println("Good");
        break;
    default:
        System.out.println("Keep going");
}
Remember
  • Without break, execution "falls through" into the next case.
  • default is optional but good practice.
  • Works with int, char, String, and enums.
Common Mistake

Forgetting break and silently falling through into unrelated cases.

DSA Connection

Less common than if-else in DSA, but useful for state-machine style problems.

› for Loop

Concept

The workhorse loop for anything with a known number of iterations — the backbone of array and string traversal.

Example

Main.java
for (int i = 0; i < n; i++) {
    // work with i
}
Remember
  • Three parts: initialization, condition, update — all optional, but almost always all three are used.
  • The condition is checked before every iteration, including the first.
  • for (int i = n - 1; i >= 0; i--) walks backward — just as common.
Common Mistake

Using <= instead of < against a length, causing one extra out-of-bounds iteration.

DSA Connection

This is how you traverse arrays and strings, and build the outer/inner loops of nested-loop algorithms.

› while and do-while Loops

Concept

while checks the condition before each iteration and may run zero times. do-while checks after, so the body always runs at least once.

Example

Main.java
int i = 0;
while (i < n) {
    i++;
}

int choice;
do {
    choice = sc.nextInt();
} while (choice != 0);
Remember
  • Use while when the number of iterations isn't known ahead of time.
  • do-while guarantees at least one execution.
  • An easy-to-miss infinite loop happens when the loop variable is never updated inside the body.
Common Mistake

Updating the condition variable only inside an if that doesn't always execute — accidentally creating an infinite loop.

DSA Connection

Two-pointer techniques, binary search, and "keep dividing by 2" patterns are almost always written as while loops.

› break and continue

Concept

break exits the nearest loop immediately. continue skips the rest of the current iteration and moves to the next one.

Example

Main.java
for (int i = 0; i < arr.length; i++) {
    if (arr[i] == target) break;      // stop searching
    if (arr[i] < 0) continue;         // skip negatives
    System.out.println(arr[i]);
}
Remember
  • break only exits the innermost loop.
  • continue still runs the loop's update statement before moving on.
  • Overusing either can make control flow hard to trace — use them for genuinely early exits.
Common Mistake

Assuming break inside a nested loop exits both loops — it only exits the one it's directly inside.

DSA Connection

break is exactly how a linear search stops the moment it finds a match instead of scanning the rest of the array for nothing.

› How to Calculate Loop Complexity

Concept

Count how many times the loop body runs relative to input size n. A single pass over n elements is O(n); a loop nested inside another roughly multiplies.

Example

Main.java
for (int i = 0; i < n; i++) { }             // O(n)

for (int i = 0; i < n; i++)                 // O(n^2)
    for (int j = 0; j < n; j++) { }

while (n > 1) { n /= 2; }                   // O(log n)
Remember
  • Single loop over n → O(n).
  • Nested loops, both up to n → O(n²).
  • A loop that divides (or multiplies) its variable each step → O(log n).
Common Mistake

Assuming two sequential (not nested) loops over n are O(n²) — back-to-back loops add, they don't multiply: O(n) + O(n) is still O(n).

DSA Connection

This is literally how you'll answer "what's the time complexity of your solution?" in every interview — trace the loops, not the code.

03 / 12

Methods / Functions

DSA solutions are almost always a single method with a very specific signature. Get fluent with writing and calling them.

› Declaring & Calling Methods

Concept

A method is a named, reusable block of code with a return type, a name, and parameters. void means it returns nothing.

Example

Main.java
static int sum(int a, int b) {
    return a + b;
}

int total = sum(4, 7);   // calling it
Remember
  • The return type must match what's actually returned — every code path in a non-void method must return a value.
  • Parameters are local to the method; they don't affect the caller's primitive variables.
  • A method can have zero, one, or multiple parameters, but only one return type.
Common Mistake

Forgetting a return on a code path (e.g. inside an if without a matching else) — this won't even compile for non-void methods.

DSA Connection

Nearly every solution you write is one method with a fixed signature like int[] twoSum(int[] nums, int target) — this is the shape of the answer, every time.

› Static Methods

Concept

static means the method belongs to the class itself, not to an instance — you can call it without creating an object first.

Example

MathUtils.java
class MathUtils {
    static int square(int x) {
        return x * x;
    }
}
// no "new" needed:
int result = MathUtils.square(5);
Remember
  • main is always static, so any method called directly from main() must be static too (unless called on an object).
  • Static methods can't access instance variables directly.
  • Helper methods in a single-class DSA solution are almost always static.
Common Mistake

Trying to call a non-static method directly from a static main() without creating an object first — a very common first compiler error.

DSA Connection

Utility/helper functions (isPrime, gcd, swap) are written static because they don't need any object state.

› Method Overloading

Concept

Two or more methods can share a name as long as their parameter lists differ. Java picks the right one based on the arguments you pass.

Example

Main.java
static int add(int a, int b) { return a + b; }
static double add(double a, double b) { return a + b; }
static int add(int a, int b, int c) { return a + b + c; }
Remember
  • Overloading is resolved at compile time, based on argument types.
  • Return type alone is not enough to overload a method — parameters must differ.
  • Constructors can be overloaded too — a Node(int data) next to a Node(int data, Node next).
Common Mistake

Trying to "overload" two methods that differ only in return type — this doesn't compile.

DSA Connection

You'll see this most in constructors — one that takes just a value, and one that also takes a pointer to the next node.

› Passing Arrays to Methods

Concept

Arrays are objects in Java, so they're passed by reference — a method that modifies the array's contents changes the original.

Example

Main.java
static void doubleValues(int[] arr) {
    for (int i = 0; i < arr.length; i++) {
        arr[i] *= 2;
    }
}
// after calling doubleValues(nums), nums itself is changed
Remember
  • Reassigning the parameter (arr = new int[5]) inside the method does not affect the caller's array — only mutating existing elements does.
  • This is why many DSA methods modify an array in place and return void.
  • Same is true for any object (ArrayList, custom classes) — the reference is passed by value.
Common Mistake

Expecting a method to "resize" the caller's array by assigning a brand-new array to the parameter — that only rebinds the local variable.

DSA Connection

In-place algorithms (reverse an array, sort in place, two-pointer swap) rely entirely on this behavior.

04 / 12

Arrays ★★★ High Priority

The single most important prerequisite on this page — comfortable, reflexive array manipulation is what the rest of DSA is built on.

› Creating & Initializing Arrays

Concept

An array is a fixed-size, ordered block of same-typed values. Size is set once, at creation, and can't change afterward. Array indexing starts from 0.

Example

Main.java
int[] arr = {10, 20, 30, 40};
int[] empty = new int[5];        // all zeros
int[] copy = new int[]{1, 2, 3};
Remember
  • The first element is arr[0], the last is arr[arr.length - 1].
  • new int[5] creates 5 elements, all defaulted to 0.
  • Array length is fixed forever — "resizing" means creating a new, bigger array and copying values over.
Common Mistake

ArrayIndexOutOfBoundsException: confusing the declared size (5) with a valid index — arr[5] on a 5-element array is out of range; valid indices are 0 to 4.

DSA Connection

Arrays are the base case almost every other data structure (ArrayList, Stack, hash table buckets) is built on top of.

› Traversal & Updating Elements

Concept

Visiting every element, usually with a for loop, to read or update its value.

Example

Main.java
int[] arr = {10, 20, 30, 40};
for (int i = 0; i < arr.length; i++) {
    System.out.println(arr[i]);
    arr[i] = arr[i] + 1;   // update in place
}
Remember
  • arr.length is a field, not a method — no parentheses.
  • The enhanced for loop (for (int x : arr)) is great for reading but can't update the array through x.
  • Traversal is O(n) — you touch every element exactly once.
Common Mistake

Writing for (int i = 0; i <= arr.length; i++) — the <= causes an out-of-bounds access on the last iteration.

DSA Connection

Every array-based algorithm starts with the ability to traverse cleanly and correctly.

› Finding Max/Min & Searching

Concept

Scanning the array once, keeping a running best value (for max/min) or comparing each element to a target (for search).

Example

Main.java
int max = arr[0];
for (int i = 1; i < arr.length; i++) {
    if (arr[i] > max) max = arr[i];
}

int target = 30, index = -1;
for (int i = 0; i < arr.length; i++) {
    if (arr[i] == target) { index = i; break; }
}
Remember
  • Always initialize max/min to the first element, not to 0.
  • Linear search is O(n); binary search on a sorted array is O(log n).
  • break as soon as you find what you're looking for.
Common Mistake

Initializing max to 0 when the array might contain only negative values — silently producing the wrong answer.

DSA Connection

This exact pattern — a running best value updated in a single pass — is the skeleton of a huge share of array problems.

› Reversing & Copying Arrays

Concept

Reversing swaps elements from both ends toward the middle. Copying duplicates values into a new array so the original is untouched.

Example

Main.java
int left = 0, right = arr.length - 1;
while (left < right) {
    int temp = arr[left];
    arr[left] = arr[right];
    arr[right] = temp;
    left++; right--;
}

int[] copy = Arrays.copyOf(arr, arr.length);
Remember
  • In-place reversal: two pointers and a temp variable — O(n) time, O(1) extra space.
  • int[] b = a; does not copy — b and a point to the same array.
  • Arrays.copyOf() and .clone() both create a genuine new array.
Common Mistake

Writing int[] copy = original; expecting an independent array — both variables reference the same underlying data.

DSA Connection

The two-pointer swap pattern here is the same one used in palindrome checks, sorting, and reversing linked lists.

› 2D Arrays

Concept

An array of arrays — used for grids, matrices, and adjacency matrices in graph problems.

Example

Main.java
int[][] grid = {
    {1, 2, 3},
    {4, 5, 6}
};
for (int row = 0; row < grid.length; row++) {
    for (int col = 0; col < grid[row].length; col++) {
        System.out.print(grid[row][col] + " ");
    }
}
Remember
  • grid.length is the row count; grid[row].length is the column count of that row.
  • Rows can technically have different lengths ("jagged arrays") — most DSA problems assume they don't.
  • Traversal is almost always a nested loop: outer for rows, inner for columns.
Common Mistake

Using grid.length where grid[0].length (column count) was meant, especially in non-square grids.

DSA Connection

Matrix problems, grid-based BFS/DFS, and dynamic programming tables are all built on 2D arrays.

› The Arrays Utility Class

Concept

java.util.Arrays provides ready-made static methods so you don't hand-write common array operations.

Example

Main.java
import java.util.Arrays;

int[] arr = {5, 3, 1, 4};
Arrays.sort(arr);                    // [1, 3, 4, 5]
System.out.println(Arrays.toString(arr));
int[] copy = Arrays.copyOf(arr, arr.length);
Remember
  • Arrays.sort() sorts in place, O(n log n) for primitives.
  • Arrays.toString() is the easy way to print an array's contents.
  • Arrays.fill(arr, value) sets every element to the same value in one call.
Common Mistake

Calling System.out.println(arr) directly and getting something like [I@1b6d3586 instead of the actual values.

DSA Connection

You'll reach for Arrays.sort() constantly as a first step before two-pointer or binary-search approaches.

Strings ★★★ High Priority

Strings behave like read-only arrays of characters with a lot of built-in helper methods. Know the handful that actually get used.

› Creating Strings & Basic Methods

Concept

A String is a sequence of characters. length() gives the character count, charAt(i) gets the character at an index.

Example

Main.java
String s = "hello";
System.out.println(s.length());     // 5
System.out.println(s.charAt(0));    // 'h'
Remember
  • length() is a method (with parentheses) on String; length is a field (no parentheses) on arrays.
  • Strings are immutable — no method ever changes the original; they all return a new string.
  • Indexing is 0-based, same as arrays.
Common Mistake

Writing s.length instead of s.length(), or arr.length() instead of arr.length.

DSA Connection

charAt() and length() are the two building blocks of every string-traversal solution.

› substring(), equals(), compareTo()

Concept

substring() extracts part of a string. equals() checks if two strings hold the same characters. compareTo() gives ordering.

Example

Main.java
String s = "hello world";
System.out.println(s.substring(0, 5));         // "hello"
System.out.println(s.equals("hello world"));   // true
System.out.println("apple".compareTo("banana")); // negative
Remember
  • substring(start, end) — end is exclusive.
  • Never use == to compare string contents — it compares references, not characters.
  • compareTo() returns negative/zero/positive — never rely on the exact magnitude, only the sign.
Common Mistake

Using == to compare two strings for equality — it may "work" in simple tests and then fail once a string is built dynamically.

DSA Connection

equals() is essential for correctness (HashMap keys, duplicate checks); substring() shows up in every sliding-window and palindrome problem.

› String Traversal & toCharArray()

Concept

Loop through characters with charAt(), or convert to a char[] once with toCharArray() if you need repeated indexed access.

Example

Main.java
String s = "hello";
for (int i = 0; i < s.length(); i++) {
    System.out.println(s.charAt(i));
}

char[] chars = s.toCharArray();
Remember
  • toCharArray() is worth it when you're accessing characters many times.
  • A char[] can be modified in place; the original String never can.
  • String and char[] are genuinely different types — some methods only accept one.
Common Mistake

Trying to reverse a String "in place" — Strings are immutable, so convert to a char[] or StringBuilder first.

DSA Connection

Almost every string DSA problem (anagrams, palindromes, character frequency) starts with this decision.

› StringBuilder

Concept

A mutable sequence of characters, used whenever you're building or modifying a string repeatedly — far more efficient than concatenating Strings in a loop.

Example

Main.java
StringBuilder sb = new StringBuilder();
sb.append("hello");
sb.append(" world");
sb.reverse();
sb.deleteCharAt(0);
String result = sb.toString();
Remember
  • append(), insert(), delete(), reverse() all modify it in place.
  • Convert back with toString() when done.
  • Building a string with += inside a loop is O(n²) total; StringBuilder.append() is O(1) amortized per call.
Common Mistake

Using String += inside a loop that runs many times, silently turning an O(n) solution into O(n²).

DSA Connection

The standard tool for building an output string, reversing a string, or doing in-place-style character manipulation.

Basic OOP Required for DSA

Just enough OOP to write a Node class with a straight face — not a full object-oriented design course.

› Class & Object

Concept

A class is a blueprint; an object is a specific instance created from it, with its own copy of the instance variables.

Example

Point.java
class Point {
    int x;
    int y;
}

Point p1 = new Point();
p1.x = 3;
p1.y = 4;
Remember
  • new Point() creates a new object in memory and returns a reference to it.
  • Each object has its own copies of instance variables.
  • A class can contain variables (state) and methods (behavior).
Common Mistake

Forgetting new when creating an object — Point p1; alone just declares a reference that is null.

DSA Connection

Custom classes are how you model anything that isn't a plain number or string — linked list nodes, tree nodes, graph edges.

› Constructors & this

Concept

A constructor runs automatically when an object is created. this refers to the current object, used to tell an instance variable apart from a same-named parameter.

Example

Point.java
class Point {
    int x, y;
    Point(int x, int y) {
        this.x = x;
        this.y = y;
    }
}
Point p = new Point(3, 4);
Remember
  • A constructor has the same name as the class and no return type — not even void.
  • this.x = x means "this object's x field = the parameter x."
  • Writing your own constructor removes Java's invisible free default one.
Common Mistake

Naming a parameter the same as the field and forgetting this. — without it, x = x just assigns the parameter to itself.

DSA Connection

Constructors are how a Node gets its data (and often its next pointer) set the moment it's created.

› Building a Node Class for DSA

Concept

A tiny custom class holding a value and a reference to another node — the fundamental building block of linked lists, trees, and graphs.

Example

Node.java
class Node {
    int data;
    Node next;

    Node(int data) {
        this.data = data;
        this.next = null;
    }
}

Node head = new Node(10);
head.next = new Node(20);
Remember
  • next starts as null, meaning "nothing after this node yet."
  • Following .next repeatedly is how you walk a linked list.
  • For trees, the same idea becomes left and right instead of a single next.
Common Mistake

Forgetting to initialize next to null and getting a confusing NullPointerException much later, far from the actual bug.

DSA Connection

This exact 5-line class is the entire foundation for linked lists, binary trees, and graph adjacency nodes.

› Basic Inheritance Concept

Concept

A class can extend another class, inheriting its fields and methods and optionally overriding them.

Example

Animal.java
class Animal {
    void speak() { System.out.println("..."); }
}
class Dog extends Animal {
    @Override
    void speak() { System.out.println("Woof"); }
}
Remember
  • extends creates an "is-a" relationship — a Dog is an Animal.
  • @Override is optional but recommended — it makes the compiler check the signature actually matches.
  • You won't write much inheritance in typical DSA solutions, but you'll see it in provided class templates.
Common Mistake

Assuming a subclass automatically gets a constructor from its parent — constructors aren't inherited, though you can call one explicitly with super(...).

DSA Connection

More relevant for larger object-oriented codebases than day-to-day DSA problems — know it exists, don't over-invest here.

Recursion ★★★★★ Very High Priority

The single highest-leverage topic on this page. If recursion still feels shaky, everything from linked lists onward will feel harder than it needs to.

› What Is Recursion?

Concept

A method that calls itself to solve a smaller version of the same problem, until the problem is small enough to answer directly.

Example

Main.java
static void print(int n) {
    if (n == 0) return;         // base case
    System.out.println(n);
    print(n - 1);               // recursive case
}
Remember
  • Every recursive method needs a base case (when to stop) and a recursive case (how to shrink the problem).
  • Recursion trades explicit looping for the call stack doing the bookkeeping for you.
  • Anything recursion can do, a loop plus an explicit stack can also do — recursion is often just clearer to write and read.
Common Mistake

Writing the recursive case correctly but never actually reaching the base case (e.g. calling print(n) instead of print(n - 1)) — infinite recursion.

DSA Connection

Recursion is the natural way to express tree traversal, backtracking, divide-and-conquer, and many DP solutions.

› Base Case & Recursive Case

Concept

The base case is the simplest version of the problem, answered directly. The recursive case reduces the problem and calls the method again.

Example

Main.java
static int factorial(int n) {
    if (n == 0) return 1;          // base case
    return n * factorial(n - 1);   // recursive case
}
Remember
  • The base case must be reachable — every recursive call has to move strictly closer to it.
  • A function can have more than one base case (e.g. n == 0 and n == 1 for Fibonacci).
  • If you can't identify the base case, you can't safely write the recursion.
Common Mistake

Writing the wrong base case, like checking n <= 0 when negative inputs should never occur — it silently hides a bug instead of surfacing it.

DSA Connection

This base-case-then-recursive-case shape is the template for every recursive solution you'll write.

› The Call Stack

Concept

Each recursive call is pushed onto the call stack, paused, waiting for the call it made to return. Once a call reaches its base case and returns, the stack unwinds back through every paused call in reverse order.

Example

trace
print(3)
 → print(2)
    → print(1)
       → print(0)   // base case, returns
    ← returns to print(1), which finishes
 ← returns to print(2), which finishes
← returns to print(3), which finishes
Remember
  • Each call gets its own separate copy of local variables and parameters.
  • Too much recursion depth causes a StackOverflowError.
  • Work written before the recursive call happens on the way "down"; work written after it happens on the way back "up" during unwinding.
Common Mistake

Assuming a recursive function has already returned once you write the line after the recursive call — that line only runs once every deeper call has fully finished and unwound back to this one.

DSA Connection

Understanding unwinding is exactly what's needed to trace how a recursive Fibonacci, tree traversal, or backtracking solution accumulates its answer.

› Recursion with Arrays & Strings

Concept

Recursion on arrays/strings usually shrinks the problem by moving an index forward each call, instead of creating a new smaller array every time.

Example

Main.java
static int sumArray(int[] arr, int index) {
    if (index == arr.length) return 0;          // base case
    return arr[index] + sumArray(arr, index + 1);
}
// initial call: sumArray(arr, 0)
Remember
  • Pass the array by reference and use an index parameter to track position.
  • The base case is almost always "index reached the end" or "left pointer passed right pointer."
  • This same index-shrinking idea works identically for strings.
Common Mistake

Recomputing a sliced sub-array or sub-string on every recursive call instead of passing an index — quietly turns an O(n) traversal into something much slower.

DSA Connection

This index-based pattern is exactly how you'll write recursive binary search, and it sets up array/string divide-and-conquer later.

Practice before moving on

Trace these by hand — base case, recursive case, and the call stack — before checking any solution online:

  • Print numbers 1 to N (ascending — think about which line runs before vs. after the recursive call).
  • Find the factorial of N.
  • Find the sum of the first N numbers.
08 / 12

Java Collections ★★★★★ Very High Priority

Java's built-in collections do in one line what would otherwise take twenty. Fluency here is what makes solutions fast to write, not just fast to run.

› ArrayList

Concept

A resizable array — unlike int[], it grows automatically as you add elements, at the cost of some overhead, and it only holds object types.

Example

Main.java
ArrayList<Integer> list = new ArrayList<>();
list.add(10);
list.add(20);
System.out.println(list.get(0));   // 10
list.set(0, 99);
list.remove(1);
System.out.println(list.size());
Remember
  • ArrayList<Integer>, not ArrayList<int> — generics only work with object (wrapper) types.
  • get(index) is O(1); add() at the end is amortized O(1), but middle insert/remove is O(n).
  • contains() does a linear scan — O(n), not instant.
Common Mistake

Reaching for a plain array when the size isn't known ahead of time, then hand-rolling resize logic that ArrayList already handles correctly.

DSA Connection

Use ArrayList when the collection's size changes during the algorithm; use int[] when the size is fixed and known upfront.

› HashMap

Concept

Stores key → value pairs with (average case) O(1) insertion and lookup by key. Probably the single most-used collection in DSA outside of arrays.

Example

Main.java
HashMap<Integer, Integer> map = new HashMap<>();
map.put(1, 100);
map.put(2, 200);
System.out.println(map.get(1));          // 100
System.out.println(map.containsKey(3));  // false
map.remove(2);
Remember
  • put() on an existing key overwrites its value — it doesn't add a duplicate entry.
  • get() on a missing key returns null, not an exception.
  • getOrDefault(key, 0) is a clean way to handle frequency counting without a manual check.
Common Mistake

Calling get() on a missing key and using the result directly — unboxing a null into a primitive throws NullPointerException.

DSA Connection

The go-to structure for frequency counting, duplicate detection, caching, and the classic Two Sum pattern (value → index).

› HashSet

Concept

A collection of unique elements with no guaranteed order — essentially a HashMap that only cares about the keys.

Example

Main.java
HashSet<Integer> seen = new HashSet<>();
seen.add(5);
seen.add(5);              // ignored, already present
System.out.println(seen.contains(5));  // true
System.out.println(seen.size());       // 1
Remember
  • add() silently does nothing if the element is already present.
  • contains() is (average case) O(1) — what makes HashSet useful for membership checks.
  • Doesn't preserve insertion order — use LinkedHashSet if you need that.
Common Mistake

Expecting iteration order to match insertion order — with a plain HashSet, it's unspecified.

DSA Connection

The standard way to detect duplicates in one pass, track "visited" nodes in graph traversal, or check membership without scanning a list.

09 / 12

Stack

Last-In-First-Out — the most recently added element is the first one removed.

› Stack (LIFO) with Deque

Concept

Modern Java code uses the Deque interface (backed by ArrayDeque) instead of the old Stack class for LIFO behavior.

Example

Main.java
Deque<Integer> stack = new ArrayDeque<>();
stack.push(10);
stack.push(20);
System.out.println(stack.peek());  // 20
stack.pop();                       // removes 20
System.out.println(stack.isEmpty());
Remember
  • push() adds to the top, pop() removes and returns the top, peek() looks without removing.
  • All three operations are O(1).
  • The legacy java.util.Stack is synchronized (slower) and extends Vector — prefer Deque via ArrayDeque in modern code.
Common Mistake

Calling pop() or peek() on an empty stack — throws NoSuchElementException; check isEmpty() first when it's not guaranteed to have elements.

DSA Connection

Matching parentheses, undo operations, expression evaluation, and the classic "Next Greater Element" pattern all rely on a stack.

10 / 12

Queue

First-In-First-Out — the earliest added element is the first one removed.

› Queue (FIFO) with Deque

Concept

Also implemented with ArrayDeque, through the Queue interface.

Example

Main.java
Queue<Integer> queue = new ArrayDeque<>();
queue.add(10);
queue.add(20);
System.out.println(queue.peek());  // 10
queue.poll();                      // removes 10
System.out.println(queue.isEmpty());
Remember
  • add()/offer() inserts at the back; poll() removes the front; peek() looks without removing.
  • poll() returns null on an empty queue; remove() throws instead — know the difference.
  • All core operations are O(1).
Common Mistake

Using pop()/push() (stack vocabulary) on a Queue reference — its interface uses add/offer and remove/poll.

DSA Connection

Queues are the backbone of BFS (breadth-first search) and level-order tree traversal.

11 / 12

PriorityQueue ★★★★ High Priority

Java's built-in heap implementation — how you solve "top K" and heap problems without writing a heap from scratch.

› PriorityQueue (Heap)

Concept

Elements come out in priority order (smallest first, by default) rather than insertion order.

Example

Main.java
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
minHeap.add(5);
minHeap.add(1);
minHeap.add(3);
System.out.println(minHeap.poll());  // 1 (smallest first)

PriorityQueue<Integer> maxHeap =
    new PriorityQueue<>(Collections.reverseOrder());
maxHeap.add(5);
maxHeap.add(1);
System.out.println(maxHeap.poll());  // 5 (largest first)
Remember
  • Default PriorityQueue is a min-heap; pass Collections.reverseOrder() (or a Comparator) for a max-heap.
  • add()/poll() are O(log n); peek() is O(1).
  • Iterating a PriorityQueue directly does not give sorted order — only repeated poll() calls do.
Common Mistake

Assuming a for-each loop over a PriorityQueue visits elements smallest-to-largest — the internal array order is heap order, not sorted order.

DSA Connection

The direct tool for Kth largest/smallest, "Top K frequent elements," merging K sorted lists, and Dijkstra's shortest-path algorithm.

› Big-O Notation

Concept

Big-O describes how an algorithm's running time (or memory use) grows as input size n grows — a way to talk about performance independent of the specific machine.

Example

Main.java
arr[0];                        // O(1)  — constant

for (int i = 0; i < n; i++) { }        // O(n) — linear

while (n > 1) { n /= 2; }     // O(log n) — logarithmic
Remember
  • O(1): constant, doesn't grow with input (array access, HashMap get on average).
  • O(log n): shrinks the problem by a fraction each step (binary search).
  • O(n): one pass over the input.
  • O(n log n): linear work repeated log n times (efficient sorting).
  • O(n²): nested loops over the same input.
  • O(2ⁿ): work doubles with every additional input element (naive recursive Fibonacci, generating all subsets).
Common Mistake

Confusing "fast in practice for small inputs" with "good complexity" — an O(n²) algorithm can outrun an O(n log n) one when n is tiny, but that flips hard as n grows.

DSA Connection

This is the vocabulary every solution gets judged by — both an automated judge's time limit and an interviewer's expectations.

› Simplifying Complexity

Concept

Big-O describes growth trend, so constants and smaller terms get dropped — they stop mattering once n is large enough.

Example

Main.java
// O(2n) simplifies to O(n)
for (int i = 0; i < n; i++) { }
for (int i = 0; i < n; i++) { }

// O(n^2 + n) simplifies to O(n^2)
// the n^2 term dominates once n is large
Remember
  • Drop constants: O(2n), O(n/2), and O(n + 5) are all just O(n).
  • Drop lower-order terms: O(n² + n) is O(n²).
  • Space complexity follows the same rules but measures extra memory — a recursive call stack counts too.
  • "Amortized" complexity (like ArrayList.add()) means occasionally slow operations average out to fast over many calls.
Common Mistake

Reporting complexity without simplifying — saying "O(n + n)" instead of "O(n)" isn't wrong, but it's not how it's communicated.

DSA Connection

Simplification is exactly what lets you compare two very differently-written solutions at a glance and say which one scales better.

Two simplification rules to know cold: drop constants (O(2n) → O(n)) and drop lower-order terms (O(n² + n) → O(n²)). Big-O only cares about the dominant term as n gets large.

Common Java Mistakes in DSA

Eleven mistakes that show up over and over in DSA code — bad vs. good, side by side.

== vs .equals() for Strings

== compares object references, not contents. Two equal-looking strings can be different objects.

if (s1 == s2) if (s1.equals(s2))

Array Index Errors

Valid indices run from 0 to length - 1. Using <= reads one past the end.

for (int i=0; i<=arr.length; i++) for (int i=0; i<arr.length; i++)

Integer Overflow

int maxes out around 2.1 billion and wraps silently — no exception is thrown.

int result = bigNum1 * bigNum2; long result = (long) bigNum1 * bigNum2;

Using int When long Is Required

Values like large factorials or products blow past int's range fast.

int factorial = compute(20); long factorial = compute(20);

Forgetting static

main() is static, so anything it calls directly must be static too.

int helper() { ... } static int helper() { ... }

length vs length()

length is a field on arrays; length() is a method on String.

arr.length() / str.length arr.length / str.length()

Modifying a Collection While Iterating

Structurally changing a list mid-for-each throws ConcurrentModificationException.

for (int x : list) list.remove(x); it.remove(); // via Iterator

Forgetting the Base Case in Recursion

Without a reachable base case, recursion runs until StackOverflowError.

void f(int n) { f(n-1); } void f(int n) { if (n==0) return; f(n-1); }

Not Checking Empty Arrays/Collections

Accessing index 0 on an empty array throws immediately — guard against empty input first.

int first = arr[0]; if (arr.length == 0) return -1;

Off-by-One Errors

Mixing 1-based counting with 0-based indexing skips arr[0] or reads one past the end.

for (int i=1; i<=n; i++) sum += arr[i]; for (int i=0; i<n; i++) sum += arr[i];

Integer Division Mistakes

If both operands are int, division happens as integer division before assignment.

double avg = sum / count; double avg = (double) sum / count;
